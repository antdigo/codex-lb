## Design

Use the existing response ID/account/count/fingerprint/pending-call fields as one response-owned snapshot. Completion replaces/clears every field in one synchronous state transition. An old alias still routes to its owner; only exact matching metadata (or the existing verified public/physical binding) can authorize trim or synthetic obligation injection. Durable latest snapshots never authorize transformations of another explicitly requested response. If metadata is unavailable, retain supplied history and refuse only unsupported replay/transform authority. No historical index is added.

A logical HTTP operation owns a frozen cache identity decision resolved from API-key override then overlaid settings. Account-specific tokens derive per physical attempt. Preparation/fingerprints retain unscoped text and headers; final body/handshake transformations apply once. Reuse records the effective mode actually used by a connection rather than reading mutable settings at send time. Independent traffic uses a compatible warm lane; exact response/turn continuation remains bound to its owner, with bounded same-owner replacement or a clear local refusal when its connection cannot satisfy the current policy. Raw handoff and owner forwarding preserve the original decision rather than reread current settings. The direct downstream WebSocket path remains outside the existing identity coverage contract; common openers must not silently opt that path in.

Minimality: reuse existing lifecycle/controller, request/API metadata and compatible-lane selection. No new retries, scoring changes, prewarm, persistent mapping or protocol assumptions. Regression evidence is the protected9counterexamples+5controls, plus missing durable/projection/policy-change cases added before each correction. Actual provider hit uplift remains a post-activation measurement, not a source/test claim.

Marked-output deduplication also waits until the execution slot has an exact owned response. A bounded transient tuple (at most256 SHA256 output identities) is replaced/cleared with that response snapshot. Candidate prefix items must be an ordered subsequence of actual completed output. Only existing wire bookkeeping and function-argument JSON whitespace are normalized; unknown metadata/opaque content remain significant. Without complete bounded output evidence, preserve the prefix. This adds no durable bodies, historical index or replay authority. Individually observed pending calls remain usable for interrupted-output repair independently of whether a complete durable manifest was established.
