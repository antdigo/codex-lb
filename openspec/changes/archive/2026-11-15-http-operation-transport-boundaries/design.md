# Design
Use the existing controller as the sole retry authority. Conclusive retryable HTTP refusals must be classified consistently with the raw retry loop and consume its shared ordinary quota; ambiguous sends remain forbidden. Preserve separate auth allowances, file/account pins and the original deadline.
Resolve recognized projected response anchors before any routing branch can bypass their owner checks. Reuse a verified owning lane where safe, or refuse before dispatch when the selected route cannot preserve the binding. Ordinary physical upstream IDs retain their existing behavior; no blind ID stripping, namespace privilege or unconstrained cross-transport translation.
This closes two verified contract gaps in the approved design; bypassing permits or treating a public ID as a physical upstream anchor are rejected because they violate that design.
Prepare a separate pinned runtime by copying the installed compatible environment and overlaying verified source, retaining unchanged dashboard assets. Activation/rollback use the established schema-identical transaction: verify identities/config, service-user offline checks and backup, stop/switch/start/health, retain current DB/refreshed tokens on rollback. Preparation never stops the service. User receives a concrete sudo activation command and rollback command.

After the database incident, local verification requires two independent boundaries: a standalone launcher configures an owned temporary home/database and enforces Landlock before importing pytest/application modules; destructive fixtures compare the actual engine and connection URL with their captured intended test URL. A mismatched preimported engine fails before connection or schema reset. Kernel denial is checked on a disposable canary and inherited by subprocesses. Tests never attempt writes against production data. Unavailable containment fails closed rather than falling back to ordinary host pytest.
